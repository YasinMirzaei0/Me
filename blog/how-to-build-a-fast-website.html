How to build a fast website: 8 habits that matter

26 October 2026 · 5 min read · Yasin Mirzaei

Most slow websites were not slowed down by one big mistake. They got slow one decision at a time: an extra font, a heavy slider, an image nobody resized. The good news is that the reverse is also true. A handful of habits, applied from the first day of a project, keeps a site fast without a painful clean-up at the end.

Google’s Core Web Vitals give a useful target. For a page to count as “good”, the largest content element should appear within 2.5 seconds (LCP), interactions should respond within 200 milliseconds (INP), and the layout should barely move while loading (CLS under 0.1).

1. Set a budget before you design

Decide early how heavy the page may be and how much JavaScript you are willing to ship. A budget turns “this feels slow” into a number you can check, and it makes it easy to say no to one more effect or one more library.

2. Use modern image formats at the right size

Images are usually the heaviest part of a page. Export WebP or AVIF, resize to the largest size the layout really needs, and use srcset so phones do not download desktop-sized files.

3. Always give images a width and height

When the browser knows the dimensions up front, it reserves the space before the file arrives. This single habit removes most layout shift.

4. Lazy-load below the fold, but never the hero

Add loading="lazy" to images further down the page. Keep the main hero image eager, because it is often the element that decides your LCP score.

5. Keep fonts under control

One family and two or three weights are enough for most sites. Use font-display: swap so text is visible immediately, and host the font files yourself to avoid an extra connection to another server.

6. Ship less JavaScript

Ask whether a small piece of plain JavaScript can replace a whole library. Every kilobyte has to be downloaded, parsed and executed, and on a mid-range phone that cost is real.

7. Animate only transform and opacity

These two properties can be handled by the GPU without recalculating the layout. Animating width, height or top forces the browser to do much more work on every frame.

8. Test on a real, average phone

Your development machine is the fastest device your visitors will never own. Test on a mid-range phone, throttle the network in DevTools, and run Lighthouse or PageSpeed Insights before every launch.
